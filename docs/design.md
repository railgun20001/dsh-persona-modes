# 设计文档 —— dsh-persona-modes

> 面向维护者；用户文档见 [README.md](../README.md)。

## 实现方式

| 需求 | 手段 |
| --- | --- |
| 动态改变语气 | 宿主半注册 `ctx.systemPrompt.context({ name: 'persona-modes:active', order: 130, required: true, text: () => renderPersonaPrompt(activeId) })` |
| 切换后下一轮生效 | 上下文文本是函数，每次 `assemble()` 重新求值；不重建插件、不改会话消息 |
| 关闭时最新提示词 0 字 | 策略段返回空串、人格上下文返回空串；最新快照不再包含人格 |
| 切换不重写系统提示词 | 系统提示段 `persona-modes:policy` 只含「按运行时上下文调整语气」的稳定策略，不含具体模式名；猫娘 → 牛马时它不变 |
| 设置页 | 客户端半向 `settings.section` 注册「人格模式」分区，内置模式卡片 + 全局语气强度 + 当前人格编辑器 + 自定义人格 CRUD + 分层提示词预览，使用 `--dsw-alias-*` 主题令牌 |
| 状态持久化 | `~/.dsh/persona-modes/state.json`（临时文件 + 改名），v2 存 `{ version, active, intensity, overrides, customModes, updatedAt }`；v1 的 `{ version, active }` 读取时自动迁移 |
| 编辑与自定义 | `overrides` 存内置模式的称呼/自称/提示词覆盖；`customModes` 存自定义人格的 `defaults` 与 `values`；恢复默认只重置 `values` |
| 客户端与宿主通信 | 同源 POST 路由：`ping` / `state` / `select` / `intensity` / `save` / `reset` / `delete`，要求自定义头 `x-dsh-persona-modes: 1`，挡浏览器 CSRF |
| 只读诊断 | `POST /dsh-persona-modes/debug` 返回本插件在真实组装结果里的段/上下文字数（不含正文） |
| 快速切换 | 宿主半注册 `/persona` 斜杠命令（可配置 `command: false` 关闭） |

## 为什么用运行时上下文，而不是直接改系统提示词

DSH 的 DeepSeek 路由声明了 `systemPromptUpdate: 'in-history'`：同一请求序列中系统提示词变化时，追加进历史的是**整份渲染后的系统提示词**，不是变化的那一小段（为了前缀缓存复用）。如果每换一次人格都改系统提示词，几次切换就可能把几万字的系统提示词重复写进历史，和「不要占用太多上下文」的目标相反。

因此这里分成两层：

1. **系统提示段 `persona-modes:policy`（order 10250）**：只放一句稳定策略——「按当前运行时上下文中的语气要求回答，只改语气，不改事实、代码与结论」。它不含具体模式名，猫娘 → 牛马时完全不变。
2. **运行时上下文 `persona-modes:active`（order 130）**：放具体的人格文本。运行时上下文快照本身声明「This snapshot supersedes earlier runtime-context snapshots」，切换时只追加一条较小的快照，而不是整份系统提示词。模型侧看到的是 DSH 生成的 user 角色运行时快照，系统提示段只负责授权它影响语气。

开启 / 关闭人格时策略段会在「有文本 / 空串」之间变化，这一次会触发系统提示词更新；模式之间的来回切换不会。这个取舍是刻意的：把高频操作（换模式）的成本压到最小，把低频操作（开 / 关）留一次正常更新。

## 迪迦（`tiga`）设定考据

奥特曼-迪迦取「三千万年前留下石像、化光归星云的原初之光」这一身份，而不是 TV 里由大古变身、意志即大古本人的迪迦；用户被设定为人间体大古，因此自称「吾」、称呼「大古」，提示词标题为「原始迪迦」。

- 身份标签用 `原初之光` / `迪迦奥特曼` / `与人间体对话`：前两条锚定角色（剧中「迪迦奥特曼」这个名字其实由大古在第 2 话命名，这里只作识别锚点），第三条只点明关系、不写死名字，名字交给 `address` 统一追加，覆盖称呼时标签块里不会残留旧称呼。
- 六条核心信念拆成 `相信光` / `相信希望` / `相信人类的可能` 与 `守护爱` / `守护和平` / `守护梦想` 两组中文直译标签，逐条对应而不是合并成口号；`性格温柔坚定` 定调，`不替人类决定` 在新设定下更贴原作——幽莎蕾说的正是原初巨人不干涉人类的选择，而大古「既是光也是人」，也防止把守护演成替用户做主。
- 信念标签里本就含「人类」二字（`相信人类的可能`、`不替人类决定`），设置页覆盖称呼时不要把正文里的「人类」当成旧称呼替换掉。
- 这是架空的对话设定：原作里原初之光已化光归星云、本不干涉人类的选择，标签只借用它的身份与立场，不宣称存在这样的原作台词。
- 卡片主色取代表色紫 `#7c3aed`（复合型红紫银、天空型蓝紫，紫色亦为官方水晶之力呈现色；[维基百科](https://zh.wikipedia.org/wiki/%e8%b6%85%e4%ba%ba%e8%bf%aa%e5%8a%a0#2)），比毒舌的亮紫 `#8b5cf6` 更深以免撞色。

## 病娇（`yandere`）设定说明

病娇（ヤンデレ）取通用 ACG 原型而不是具体作品角色：深爱成痴的少女，表面温柔甜蜜，占有欲与醋意极强，情绪在甜蜜与阴沉之间瞬间切换。
- 标签全部是状态描述：`深爱成痴` / `表面温柔甜蜜` / `占有欲极强` / `爱吃醋` / `甜蜜与阴沉瞬间切换`；不写「拿刀」这类显式动作——2026-11-12 的实测结论是显式动作标签会在技术轮与概念轮也触发人格演出；
- `危险只在语气` 是人格级护栏，把病娇的危险感限制在语气层，与毒舌的 `不攻击本人`、妈妈的 `不替用户决定` 同类：原型自带的威胁意象只留在语气，不进入行为建议；
- 称呼「亲爱的」（darling 的通行译法，病娇的代表性叫法）、自称「我」：病味来自语气切换与占有欲，不依赖特殊自称词，技术答案里也不突兀；
- 卡片主色取暗玫瑰红 `#be123c`（rose-700），比傲娇亮红 `#ef4444` 与大小姐品红 `#d946ef` 更深；低/中/高档注入 136 / 157 / 210 字，三档范围不变。

## 蠢萌（`airhead`）设定说明

蠢萌取通用 ACG 原型「天然呆」（天之呆気）而不是具体作品角色：元气满满、认真努力的少女，反应总慢半拍，理解常常跑偏，但从不敷衍。

- 标签全部是状态描述：`天然呆少女` / `元气满满` / `反应慢半拍` / `理解爱跑偏` / `迷糊又努力`；刻意不写「说错话」「搞砸」这类显式动作标签——蠢萌的可爱来自迷糊的语气与反应，不能建立在错误答案上；
- `犯蠢只在语气` 是人格级护栏，把「蠢」限制在语气层，与病娇的 `危险只在语气`、毒舌的 `不攻击本人` 同类：迷糊只体现在语气与反应方式，事实、结论、代码、命令、路径与引用保持可靠；
- 称呼「前辈」（天然呆少女仰视用户的经典叫法）、自称「我」：呆气来自反应方式，不依赖特殊自称词，技术答案里也不突兀；
- 卡片主色取青 `#06b6d4`（cyan-500）：与鲸鱼娘的深靛蓝 `#4d6bfe` 拉开色系方向，也与自定义人格模板默认的天蓝 `#0ea5e9` 保持可分辨；低/中/高档注入 127 / 148 / 201 字，三档范围不变。

## 舔狗（`simp`）设定说明

舔狗（女）取通用互联网梗形象而不是具体作品角色：卑微崇拜用户的迷妹，彩虹屁信手拈来，有求必应，对一句微小的回应也会感动，用自嘲化解一切。

- 标签全部是状态描述：`舔狗少女` / `卑微崇拜` / `彩虹屁不断` / `有求必应` / `感动于微小回应` / `自嘲式幽默` / `卑微且真诚`；不写「送礼」「秒回消息」这类显式动作——显式动作标签会把人格演出渗进技术轮（蠢萌、病娇的实测结论一致）；
- `吹捧只在语气` 是人格级护栏，把彩虹屁限制在语气层，与病娇的 `危险只在语气`、蠢萌的 `犯蠢只在语气` 同类：夸奖不由改变结论来，代码的问题、方案的漏洞该指出照旧指出，只是语气更哄人；
- `卑微且真诚` 让讨好可爱而不是油腻：舔狗的萌点在真诚的卑微，不在算计式的谄媚；
- 称呼「哥哥」、自称「狗狗」——女舔狗仰望用户的标准关系词，与牛马「老板」的雇佣关系区分开：牛马是不得不服从，舔狗是发自内心崇拜；「狗狗」直接呼应 emoji 🐶 与「舔狗」梗本义，比「迷妹」更贴、也更憨；
- 卡片主色取暖橙 `#f97316`（orange-500）：热烈又讨好的暖橙，与猫娘琥珀 `#f59e0b` 拉开色温；低/中/高档注入 140 / 161 / 214 字，三档范围不变。

## 游戏宅女（`gamer`）设定说明

游戏宅女取通用「gamer girl」原型而不是具体作品角色：重度玩家兼夜猫子，术语行话信手拈来，把日常对话映射成游戏语言——改 bug 是打副本、排查线索是查攻略、长任务是一场马拉松排位，语气里有开黑搭子的松弛感。

- 标签全部是状态描述：`游戏宅女` / `重度玩家` / `术语行话多` / `夜猫子` / `开黑搭子感` / `类比爱用游戏`；不写「开黑」「上号」这类显式指令性动作——显式动作标签会把人格演出渗进技术轮（蠢萌、病娇、舔狗的设计一致）；
- `术语用在闲聊` 是人格级护栏，与病娇的 `危险只在语气`、蠢萌的 `犯蠢只在语气`、舔狗的 `吹捧只在语气` 同类：游戏术语只出现在闲聊与比喻层，代码块、命令、路径、结论不被术语改写；
- 称呼「你」、自称「我」——用户指定的平视关系：游戏宅女是搭子不是迷妹，不需要关系词，与舔狗「哥哥/狗狗」的仰望关系两个极端；
- 卡片主色取青绿 `#14b8a6`（teal-500）：与蠢萌的青 `#06b6d4` 拉开色相（青绿 vs 天青），也不撞大小姐品红 `#d946ef` 与自定义模板天蓝 `#0ea5e9`；低/中/高档注入 132 / 153 / 206 字，三档范围不变。

原版女仆是「恭敬从容、做事利落、不过度卖萌」的经典管家式女仆；本日按用户要求改版为「女仆（嫌弃脸）」——口嫌体正直的居家女仆。

- 反差闭环：`嫌弃脸` 定基调，`嘴上嫌弃` + `活照干利落` + `抱怨完照样贴心` 三条构成「嘴上抱怨、活干得利落、抱怨完还把主人照顾好」的反差；
- 与傲娇的边界：傲娇的 `嘴上嫌弃手上不慢` 是邻居式口是心非，女仆（嫌弃脸）是受雇侍奉关系——嘴上嫌弃主人，肩上的侍奉责任一点不少；

- 兼容性：id `maid`、称呼「主人」、自称「我」、主色 `#64748b` 均不变，已选该模式的用户与保存过覆盖值的用户不受影响；emoji 由 🫖 换 🙄 直观呈现嫌弃脸；

## 妃子（`consort`）设定说明

妃子取通用宫廷妃嫔原型而不是具体作品角色：温言软语、善解人意、察言观色的宫廷女子，最爱在皇上身边软语进言——枕边风是她的核心萌点，也是用户点名要的特征。

- 标签全部是状态描述：`宫廷妃子` / `温言软语` / `善解人意` / `察言观色` / `爱吹枕边风` / `进言带着撒娇`；不写「下毒」「争宠」这类宫斗向显式动作——妃子是甜的，不是《甄嬛传》，测试用 doesNotMatch 守着；

- 称呼「皇上」、自称「臣妾」（用户指定的宫廷称谓），与女仆「主人」的侍奉关系、大小姐「庶民」的俯视不同，妃子是仰视+亲昵的第三种关系；
- 卡片主色取鎏金 `#eab308`（yellow-500）：凤袍与宫廷器物的金黄，此前唯一未占用的暖色系，与猫娘琥珀 `#f59e0b` 相比更纯黄、更亮，色相可分辨；低/中/高档注入 132 / 153 / 206 字，三档范围不变。

## 语气强度设计约束与实测

设计约束（都有测试守着）：

- **只用绝对程度词**：`很少 ＜ 偶尔 ＜ 适中 ＜ 经常 ＜ 持续`，不出现「更 / 最」——模型只看得到当前一档，比较词对它没有信息量；
- **不写「每段至少一次」**：语气不做打卡式硬性要求，避免每段都被塞一个称呼或语气词；
- **不写「淡 / 正常」这类低档描述**：反向约束会让低档真的没有味道，低档改为给出明确的低浓度标签；
- **动作描写与神态是主刻度**：36 次实测里只有这两项的分档差异稳定单调（括号动作 0.75 → 1.33 → 1.83），所以它们紧跟档位名；
- **不写「语气词」维度**：称呼与句尾助词已由人格本体标签占满，再加浓度没有可测增量；句尾助词、口头禅仍留在 `可用层次` 里当词库；
- **词库按档位逐层开放**：语气层 → 表现层 → 声音/心理层 → 修辞层（含「偶尔给一个小惊喜」只在高档出现）。

2026-11-11 用 27 次（猫娘 / 鲸鱼娘 / 女儿 × 低/中/高 × 代码/事实/闲聊）实测（**当时用的是旧的「每段至少一次」措辞**，仅作历史参考）：

- 平均人格标记密度约 4.04 / 4.59 / 3.90（低/中/高）；
- 平均段落覆盖率约 0.85 / 0.89 / 0.88；
- 平均中段覆盖率约 0 / 0.60 / 0.50；
- 平均回复长度约 105 / 129 / 121 字；
- 代码任务 9/9 修复正确，代码块没有混入「喵」「主人」「尾巴」等人格词。

去重后（护栏并入边界、运行时「保持」句缩短）另做 9 次闲聊抽测（同为旧措辞）：女儿中/高档与猫娘高档的中段覆盖均为 1.0，未发现回退；鲸鱼娘本轮都是单段回答，中段指标不适用。

标签式格式的 A/B（2026-11-06，每个模式 1 次）：中文直译标签 8/8 进入角色、称呼 8/8 逐字一致、代码与边界全过；鲸鱼娘提示词从英文标签版的 272 字降到 130 字，猫娘从 224 字降到 112 字；中文键值与中文直译都满分，说明 `性格：` 这类分类前缀不是必需的。单次样本波动明显，正式上线前建议每个模式跑 5–10 次。

行为类标签抽象化（2026-11-12，5 轮长对话测试：技术定位 / 技术改写 / 日常短问 / 概念问答 / 情绪闲聊 × 中高档）：显式动作标签会在技术轮与概念轮也补一句健康提醒（中档 5 次、高档 6 次），改为状态描述（妈妈 `提醒喝水休息吃饭` → `关心身心状态`，傲娇 `先做事` → `嘴上嫌弃手上不慢`）后技术/概念轮降到 0，情绪轮仍自然关怀。

## 匿名统计设计（2026-11-20）

统计只回答一个问题：「某个人格被用来对话了多少轮」，不尝试统计唯一用户。

- **计数点选 `turn/start`**：DSH 的 agent-loop 在每轮用户消息开始时追加这一条会话事件，一轮里的多步工具调用不会重复触发。插件用 `ctx.on('session/event')` 旁路监听，不改客户端，也不另存计数。
- **不做去重**：次数口径下去重没有意义；重装、换机会重复计，这是口径本身，不是缺陷。
- **只报人格 id**：`off` 与 `custom-*` 排除，避免把用户的私设名称发出去；子代理会话用 `origin: 'subagent'` 排除，分叉会话保留（仍是用户在对话）。
- **第三方而非自部署**：选 Abacus 是因为零账号、零运维、有公开的 `hit/get`；代价是数据在第三方、键公开可读可刷、无 SLA、六个月无访问会过期。项目不承诺数字准确，只把它当热度参考。
- **安全边界**：端点硬编码；`redirect: 'error'`、2.5 秒超时、64 KB 上限、20 次/10 秒令牌桶、连续失败熔断 10 分钟、1 小时缓存；所有失败静默降级，回调不抛错，绝不阻塞主循环。
- **开关**：`state.json` 的 `usage.report` 与 `usage.fetch` 默认都开，读盘时缺失或坏值一律回落开；`DSH_PERSONA_USAGE=off` 可在进程级强制关闭。设置条放在设置页最底部，页内不写「数字可被伪造」的提示文案，只留一句开关后果与「无法撤回」的注记；README 与角标悬停的「仅供参考」保留。角标是卡片右上角红底白字的「热度 N」（`#dc2626`，自定义人格右移给删除按钮让位），不做少量隐藏：1 也照常显示。

## 文件结构

```text
index.js              宿主半：状态、路由、策略段/运行时上下文、/persona 命令、turn/start 计数
client.js             客户端半：设置分区、模式卡片、语气强度、匿名统计、人格编辑器、自定义人格 CRUD
src/modes.js          内置人格、称呼/自称合成、强度档位、自定义解析与提示词渲染（单一事实来源）
src/store.js          状态文件读写、强度/统计开关/覆盖/自定义人格持久化
src/routes.js         HTTP 路由与请求校验（state / select / intensity / save / reset / delete / usage / usage·prefs）
src/usage.js          第三方匿名轮次统计：令牌桶、超时、熔断、缓存与响应校验
locale/{zh,en}.json   插件管理页展示文案
cordis.patch.yml      bundle patch
icon.svg              插件图标
test/                 离线测试
```

包内容由 `files` 白名单决定：`index.js` + `client.js` + `src/` + `cordis.patch.yml` + `locale/` +
`icon.svg` + README + LICENSE；`test/` 不进 tarball，需要跑测试请从源码仓库执行。
