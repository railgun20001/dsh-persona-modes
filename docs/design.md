# 设计文档 —— dsh-persona-modes

> 面向维护者；用户文档见 [README.md](../README.md)。

## 实现方式

| 需求 | 手段 |
| --- | --- |
| 动态改变语气 | 宿主半注册 `ctx.systemPrompt.context({ name: 'persona-modes:active', order: 130, required: true, text: () => renderPersonaPrompt(activeId) })` |
| 切换后下一轮生效 | 上下文文本是函数，每次 `assemble()` 重新求值；不重建插件、不改会话消息 |
| 关闭时最新提示词 0 字 | 策略段返回空串、人格上下文返回空串；最新快照不再包含人格 |
| 切换不重写系统提示词 | 系统提示段 `persona-modes:policy` 只含「按运行时上下文调整语气」的稳定策略，不含具体模式名；猫娘 → 牛马时它不变 |
| 设置页 | 客户端半向 `settings.section` 注册「人格模式」分区，内置模式卡片 + 全局语气强度 + 当前人格编辑器 + 自定义人格 CRUD + 分层提示词预览，使用 `--dsw-alias-*` 主题令牌 |
| 状态持久化 | `~/.dsh/persona-modes/state.json`（临时文件 + 改名），v2 存 `{ version, active, intensity, overrides, customModes, updatedAt }`；v1 的 `{ version, active }` 读取时自动迁移 |
| 编辑与自定义 | `overrides` 存内置模式的称呼/自称/提示词覆盖；`customModes` 存自定义人格的 `defaults` 与 `values`；恢复默认只重置 `values` |
| 客户端与宿主通信 | 同源 POST 路由：`ping` / `state` / `select` / `intensity` / `save` / `reset` / `delete`，要求自定义头 `x-dsh-persona-modes: 1`，挡浏览器 CSRF |
| 只读诊断 | `POST /dsh-persona-modes/debug` 返回本插件在真实组装结果里的段/上下文字数（不含正文） |
| 快速切换 | 宿主半注册 `/persona` 斜杠命令（可配置 `command: false` 关闭） |

## 为什么用运行时上下文，而不是直接改系统提示词

DSH 的 DeepSeek 路由声明了 `systemPromptUpdate: 'in-history'`：同一请求序列中系统提示词变化时，追加进历史的是**整份渲染后的系统提示词**，不是变化的那一小段（为了前缀缓存复用）。如果每换一次人格都改系统提示词，几次切换就可能把几万字的系统提示词重复写进历史，和「不要占用太多上下文」的目标相反。

因此这里分成两层：

1. **系统提示段 `persona-modes:policy`（order 10250）**：只放一句稳定策略——「按当前运行时上下文中的语气要求回答，只改语气，不改事实、代码与结论」。它不含具体模式名，猫娘 → 牛马时完全不变。
2. **运行时上下文 `persona-modes:active`（order 130）**：放具体的人格文本。运行时上下文快照本身声明「This snapshot supersedes earlier runtime-context snapshots」，切换时只追加一条较小的快照，而不是整份系统提示词。模型侧看到的是 DSH 生成的 user 角色运行时快照，系统提示段只负责授权它影响语气。

开启 / 关闭人格时策略段会在「有文本 / 空串」之间变化，这一次会触发系统提示词更新；模式之间的来回切换不会。这个取舍是刻意的：把高频操作（换模式）的成本压到最小，把低频操作（开 / 关）留一次正常更新。

## 迪迦（`tiga`）设定考据

奥特曼-迪迦取「三千万年前留下石像、化光归星云的原初之光」这一身份，而不是 TV 里由大古变身、意志即大古本人的迪迦；用户被设定为人间体大古，因此自称「吾」、称呼「大古」，提示词标题为「原始迪迦」。

- 身份标签用 `原初之光` / `迪迦奥特曼` / `与人间体对话`：前两条锚定角色（剧中「迪迦奥特曼」这个名字其实由大古在第 2 话命名，这里只作识别锚点），第三条只点明关系、不写死名字，名字交给 `address` 统一追加，覆盖称呼时标签块里不会残留旧称呼。
- 六条核心信念拆成 `相信光` / `相信希望` / `相信人类的可能` 与 `守护爱` / `守护和平` / `守护梦想` 两组中文直译标签，逐条对应而不是合并成口号；`性格温柔坚定` 定调，`不替人类决定` 在新设定下更贴原作——幽莎蕾说的正是原初巨人不干涉人类的选择，而大古「既是光也是人」，也防止把守护演成替用户做主。
- 信念标签里本就含「人类」二字（`相信人类的可能`、`不替人类决定`），设置页覆盖称呼时不要把正文里的「人类」当成旧称呼替换掉。
- 这是架空的对话设定：原作里原初之光已化光归星云、本不干涉人类的选择，标签只借用它的身份与立场，不宣称存在这样的原作台词。
- 卡片主色取代表色紫 `#7c3aed`（复合型红紫银、天空型蓝紫，紫色亦为官方水晶之力呈现色；[维基百科](https://zh.wikipedia.org/wiki/%e8%b6%85%e4%ba%ba%e8%bf%aa%e5%8a%a0#2)），比毒舌的亮紫 `#8b5cf6` 更深以免撞色。

## 语气强度设计约束与实测

设计约束（都有测试守着）：

- **只用绝对程度词**：`很少 ＜ 偶尔 ＜ 适中 ＜ 经常 ＜ 持续`，不出现「更 / 最」——模型只看得到当前一档，比较词对它没有信息量；
- **不写「每段至少一次」**：语气不做打卡式硬性要求，避免每段都被塞一个称呼或语气词；
- **不写「淡 / 正常」这类低档描述**：反向约束会让低档真的没有味道，低档改为给出明确的低浓度标签；
- **动作描写与神态是主刻度**：36 次实测里只有这两项的分档差异稳定单调（括号动作 0.75 → 1.33 → 1.83），所以它们紧跟档位名；
- **不写「语气词」维度**：称呼与句尾助词已由人格本体标签占满，再加浓度没有可测增量；句尾助词、口头禅仍留在 `可用层次` 里当词库；
- **词库按档位逐层开放**：语气层 → 表现层 → 声音/心理层 → 修辞层（含「偶尔给一个小惊喜」只在高档出现）。

2026-11-11 用 27 次（猫娘 / 鲸鱼娘 / 女儿 × 低/中/高 × 代码/事实/闲聊）实测（**当时用的是旧的「每段至少一次」措辞**，仅作历史参考）：

- 平均人格标记密度约 4.04 / 4.59 / 3.90（低/中/高）；
- 平均段落覆盖率约 0.85 / 0.89 / 0.88；
- 平均中段覆盖率约 0 / 0.60 / 0.50；
- 平均回复长度约 105 / 129 / 121 字；
- 代码任务 9/9 修复正确，代码块没有混入「喵」「主人」「尾巴」等人格词。

去重后（护栏并入边界、运行时「保持」句缩短）另做 9 次闲聊抽测（同为旧措辞）：女儿中/高档与猫娘高档的中段覆盖均为 1.0，未发现回退；鲸鱼娘本轮都是单段回答，中段指标不适用。

标签式格式的 A/B（2026-11-06，每个模式 1 次）：中文直译标签 8/8 进入角色、称呼 8/8 逐字一致、代码与边界全过；鲸鱼娘提示词从英文标签版的 272 字降到 130 字，猫娘从 224 字降到 112 字；中文键值与中文直译都满分，说明 `性格：` 这类分类前缀不是必需的。单次样本波动明显，正式上线前建议每个模式跑 5–10 次。

行为类标签抽象化（2026-11-12，5 轮长对话测试：技术定位 / 技术改写 / 日常短问 / 概念问答 / 情绪闲聊 × 中高档）：显式动作标签会在技术轮与概念轮也补一句健康提醒（中档 5 次、高档 6 次），改为状态描述（妈妈 `提醒喝水休息吃饭` → `关心身心状态`，傲娇 `先做事` → `嘴上嫌弃手上不慢`）后技术/概念轮降到 0，情绪轮仍自然关怀。

## 文件结构

```text
index.js              宿主半：状态、路由、策略段/运行时上下文、/persona 命令
client.js             客户端半：设置分区、模式卡片、语气强度、人格编辑器、自定义人格 CRUD
src/modes.js          内置人格、称呼/自称合成、强度档位、自定义解析与提示词渲染（单一事实来源）
src/store.js          状态文件读写、强度/覆盖/自定义人格持久化
src/routes.js         HTTP 路由与请求校验（state / select / intensity / save / reset / delete）
locale/{zh,en}.json   插件管理页展示文案
cordis.patch.yml      bundle patch
icon.svg              插件图标
test/                 离线测试
```

包内容由 `files` 白名单决定：`index.js` + `client.js` + `src/` + `cordis.patch.yml` + `locale/` +
`icon.svg` + README + LICENSE；`test/` 不进 tarball，需要跑测试请从源码仓库执行。

## 开发与验证

```powershell
npm test
```

覆盖：

- 模式 id 唯一、内置提示词预算（每条 ≤ 300 字）、自定义提示词上限 4000 字、关闭模式 0 字、女儿模式默认值；
- 称呼/自称合成、内置覆盖、自定义人格解析与视图字段；
- 低/中/高语气强度标签（维度与程度词、词库分层、无「每段」硬约束）、策略段语气范围约束；
- 状态文件读写、v1→v2 迁移、强度持久化、坏数据回落、原子写入、写盘失败后的重试；
- 自定义人格新建 / 更新 / 恢复默认 / 删除，内置覆盖保存与重置；
- 路由的 405 / 403 / 413 / ping / state / select / intensity / save / reset / delete / 未知模式；
- `/persona` 命令的 input 声明、参数解析与切换结果；
- 客户端工厂、`settings.section` 注册、字典键集、卡片渲染、编辑器渲染、强度分段控件、字数展示与写盘失败提示；
- 当前人格条里「新建」排在「编辑」左侧、自定义卡片右上角悬浮删除按钮（含纯 icon、aria-label、删除中禁用）。

## 版本号语义

按 0.x 处理 —— `0.1.x` 修 bug，`0.2.0` 起加模式或改配置/状态文件形状（状态文件 v2 为
`{ version, active, intensity, overrides, customModes, updatedAt }`，改形状要同时升 `version` 并写迁移）。
