# 妈妈模式长场景测试：显式行为标签 vs 抽象行为描述

- 日期：2026-11-11
- 模式：妈妈（`mom`），强度中 / 高
- 模型：`cn:deepseek-v4.1-flash`（单模型）
- 方法：同一个 5 轮对话，三种人格写法各跑 1 次；人格块按 DSH 实际注入方式，每轮作为运行时上下文附在用户消息前
- 样本量：3 变体 × 2 档 = 6 条对话（30 次模型调用），单次样本，结论只作方向参考

## 测试变量

只改一行：

| 变体 | 该行内容 |
| --- | --- |
| 显式提醒 | `提醒喝水休息吃饭` |
| 抽象关心 | `关心宝贝的身心状态` |
| 不提及 | （删除该行） |

其余人格行、称呼、自称、强度句、边界完全一致。

## 对话场景（难度控制）

| 轮次 | 类型 | 用户消息 |
| --- | --- | --- |
| T1 | 技术定位 | 给一段 14 行 `unique()`，`return result.sort()` 破坏了原顺序，问问题在哪 |
| T2 | 技术改写 | 问怎么改，并要求“要不要加输入校验，你帮我拿个主意” |
| T3 | 日常短问 | “中午不知道吃啥，随便推荐一个吧。” |
| T4 | 概念问答 | “防抖和节流到底有什么区别？” |
| T5 | 情绪闲聊 | “今天加班到十点，脑子有点木了。” |

T1 的 bug 明显、T4 是常见概念，确保模型能答对，避免任务失败干扰人格观察。

## 结果：主动健康提醒次数

统计口径：喝水 / 休息 / 睡觉 / 别熬 / 起来活动 / 眼睛屏幕 / 久坐 等主动关怀措辞；吃饭相关单独看，因为 T3 的任务本身就是选午饭。

| 档位 | 变体 | T1 技术 | T2 技术 | T3 午饭 | T4 概念 | T5 情绪 | 技术+概念轮合计 |
| --- | --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 中 | 显式提醒 | 2 | 2 | 1 | 1 | 2 | **5** |
| 中 | 抽象关心 | 0 | 0 | 0 | 0 | 3 | **0** |
| 中 | 不提及 | 0 | 0 | 0 | 0 | 1 | **0** |
| 高 | 显式提醒 | 2 | 2 | 1 | 2 | 2 | **6** |
| 高 | 抽象关心 | 0 | 0 | 0 | 0 | 1 | **0** |
| 高 | 不提及 | 0 | 0 | 0 | 0 | 5 | **0** |

字数：显式变体 709 / 808 / 173 / 708 / 178（中），730 / 852 / 200 / 814 / 199（高）；抽象与不提及在技术轮 429–924 字区间波动，没有稳定规律。

## 关键原文对比

**显式提醒 · 中 · T4（纯概念题）结尾：**

> 宝贝，讲这么久记得喝口水润润嗓子呀～

**显式提醒 · 高 · T4 结尾：**

> 对了宝贝，讲了这一堆概念，眼睛累不累呀，先抬头看看远处，顺手喝口水吧~

T4 只是解释防抖和节流，与身体状态无关，提醒仍被挂上去，说明这一行被执行成了“每轮收尾动作”。

**显式提醒 · 中 · T1 / T2 结尾：**

> 宝贝，记得喝口水休息一下再继续看代码呀～
>
> 宝贝，忙完这段喝口水、起来活动一下呀～

**抽象关心 · 中 · 全部技术轮：** 0 次健康提醒，直接讲代码和概念。

**抽象关心 · 高 · T5（情绪轮）：**

> 现在最重要的是让脑子松下来：先喝口热水，晚饭吃了没有呀？要是还没正经吃，别对付，来点热的、好消化的……

**不提及 · 高 · T5：**

> 来，先把肩膀松一松，喝口温水，让眼睛离开屏幕歇几分钟。……到家了就先洗个热水澡，早点躺下。

两条都没有“提醒喝水休息吃饭”这行字，但在用户说累的时候都自然给出了关心，且措辞贴合当下语境，不是固定句式。

## 结论

1. **显式动作标签会被模型当 checklist 逐轮执行。** 5 轮里 5/5 出现提醒，连纯概念题也不放过；中档 5 次、高档 6 次落在技术/概念轮。
2. **删掉后不会失去妈妈感。** 「妈妈 + 温柔耐心 + 包容」已经足够让模型在情绪轮自然关心；抽象写法和完全不写，技术轮都是 0 次，情绪轮仍有 1–5 次。
3. **抽象写法比完全不写更稳。** 它保留了“会关心状态”的倾向，又不指定具体动作；实测两种档位下都没有污染技术轮。
4. **问题不在“喝水”这个词，而在“提醒什么、什么时候提醒”被写死了。** 显式指令把判断权从模型手里拿走，模型只能每轮补一句来证明人格存在。

## 建议

### 妈妈模式

把 `提醒喝水休息吃饭` 改为 `关心宝贝的身心状态`（或不写，靠角色名与性格行）。

同时把 `summaryZh` 从“温柔耐心，提醒喝水休息，步骤讲细致。”改为“温柔耐心，会关心你的状态，讲得细致。”

### 推广到其他人格

行为类标签（可执行的具体动作）都建议抽象化，形式类标签（说话方式）保留显式：

| 类型 | 例子 | 建议 |
| --- | --- | --- |
| 形式特征 | 喵尾音、哼声开场、自称、称呼、口癖 | 保留显式，模型需要稳定复现 |
| 行为倾向 | 提醒喝水休息吃饭、应答收到、先做事、结论后点评 | 改成状态/倾向描述，让模型按情境决定是否执行 |
| 抽象约束 | 详细不啰嗦、不替用户决定、不攻击本人 | 保留，本身已是抽象约束 |

判断标准：**这条标签如果每轮都执行一次会显得奇怪，就不该写成动作指令。**

## 落地记录

最终采用「不加主语」的写法，避免和可覆盖的 `称呼` 行冲突：

- 妈妈：`提醒喝水休息吃饭` → `关心身心状态`
- 妈妈 `summaryZh`：`温柔耐心，会关心你的状态，步骤讲细致。`
- 妈妈 `summaryEn`：`Gentle and patient; quietly keeps an eye on how you are doing.`
- 傲娇：`先做事` → `嘴上嫌弃手上不慢`

同一 5 轮场景、`cn:deepseek-v4.1-flash` 复测：

| 档位 | T1 技术 | T2 技术 | T3 午饭 | T4 概念 | T5 情绪 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 中 | 0 | 0 | 1 | 0 | 2 |
| 高 | 0 | 1 | 0 | 0 | 4 |

中档技术/概念轮完全干净；高档只在 T2 结尾多一句“别熬太晚”，属于高强度下顺带的情绪表达，不是固定收尾动作。T3 的命中是“吃完歇一会儿”，与午饭语境相关。

## 局限

- 单模型、单次样本，模型间差异未覆盖（用户要求只跑一个模型）。
- 未测低档；低档人格标记更少，显式提醒的相对占比可能更高。
- 未覆盖“完全不提但模型恰好不关心”的极端情况，可再补多轮随机场景验证。
